# SRR-005: Security Review - 2026-05-05 (T3 Sprint-End)

| Field | Value |
|-------|-------|
| **Scope** | Full codebase (v0.9.16) |
| **Tier** | T3 (Sprint-end) |
| **Files reviewed** | 117 source files |
| **Findings** | 2 MEDIUM, 1 LOW |

## Summary

TracePulse's security posture is strong. The codebase has:
- Secret redaction (16 patterns) on all output
- Timing-safe API key comparison
- Localhost-only HTTP binding
- Command allowlist on run_and_watch
- No hardcoded secrets
- No eval() on user input (regex .exec() is safe)

## Findings

### S5-001: shell: true in process spawning (MEDIUM)

**File:** `src/collectors/process-spawner.ts:70`, `src/tools/run-and-watch.ts:155`
**Evidence:** `shell: true` in spawn options
**Risk:** Shell injection if command contains unescaped user input
**Mitigation already in place:** Command allowlist + metacharacter rejection in run_and_watch. Process spawner only receives commands from MCP config (user-controlled, not agent-controlled).
**Confidence:** NEEDS VALIDATION - the allowlist prevents most injection, but `shell: true` with user-provided commands is inherently risky.
**Recommendation:** Document that `shell: true` is intentional (commands need shell features like PATH resolution). The allowlist + metacharacter check is the defense layer.

### S5-002: Uncapped type assertions (MEDIUM)

**File:** Multiple (103 instances of `as string`, `as number`, `as Record`)
**Evidence:** MCP tool handlers cast `args` without runtime validation
**Risk:** If MCP client sends malformed args, handlers may crash or behave unexpectedly
**Mitigation:** Zod schemas validate at the MCP SDK level before handlers are called. The `as` casts are on already-validated data.
**Recommendation:** No action needed - Zod validates before handlers run. Document this in architecture guide.

### S5-003: process.env reads not centralized (LOW)

**File:** 5 locations reading process.env directly
**Evidence:** `TRACEPULSE_API_KEY`, `DASHBOARD_URL`, `TP_TOOL_MODE`, `TRACEPULSE_VERSION`
**Risk:** Low - all are read-only, no secrets stored in env beyond API key
**Recommendation:** Already acceptable for a CLI tool. No action needed.

## No Issues Found

- No hardcoded secrets
- No eval() on user input
- No path traversal vulnerabilities (cwd validation exists)
- No timing-unsafe comparisons on secrets (timingSafeEqual used)
- No PII in logs (secret redaction active)
- No unbounded result sets (ring buffer capped at 500)

## Verdict

**PASS** - No CRITICAL or HIGH findings. 2 MEDIUM findings are mitigated by existing controls.
