# DRR-001 — Dependency Risk Review

**Date:** 2026-04-30
**Scope:** package.json, package-lock.json, all import statements in `src/`
**TracePulse version:** 0.9.2
**Node.js target:** ≥22.0.0

---

## Executive Summary

TracePulse has a minimal direct dependency footprint — one production dependency (`@modelcontextprotocol/sdk`) and 10 dev dependencies. No known CVEs were found (`npm audit` clean). The main risks are: (1) a phantom dependency on `zod` that works today but could break on any install, (2) a peer dependency conflict between `@eslint/js@10.x` and `eslint@9.x` that causes `npm ci` to fail, and (3) a large transitive dependency tree (91 production packages) inherited from the MCP SDK.

**Findings by severity:**

| Severity | Count |
|----------|-------|
| HIGH | 2 |
| MEDIUM | 3 |
| LOW | 3 |

## 2. Transitive Dependency Count and Risk

| Category | Count |
|----------|-------|
| Production (total) | 91 packages |
| Dev (total) | 239 packages |
| Optional | 52 packages |
| **Grand total** | 330 packages |

The 91 production transitive dependencies all come from `@modelcontextprotocol/sdk`, which bundles:

- **express@5.2.1** — full HTTP framework (body-parser, qs, side-channel, etc.)
- **hono@4.12.15** — second HTTP framework
- **ajv@8.20.0** — JSON schema validation
- **jose@6.2.2** — JWT/JWE/JWS
- **cors@2.8.6** — CORS middleware
- **eventsource@3.0.7** — SSE client
- **cross-spawn@7.0.6** — cross-platform process spawning
- **zod@4.3.6** — schema validation
- **express-rate-limit@8.4.1** — rate limiting

TracePulse itself only uses the MCP SDK's server/stdio transport and zod for tool parameter schemas. The express, hono, jose, cors, and rate-limit packages are pulled in for the SDK's HTTP/SSE transport and OAuth features that TracePulse doesn't use in stdio mode.

**Risk:** The transitive tree is large for a CLI tool. However, since TracePulse externalizes `@modelcontextprotocol/sdk` (not bundled into dist/), these packages are only installed at `npx` time and don't affect the published tarball size. The supply chain surface area is the main concern.

## 7. Missing Dependencies (Phantom Dependencies)

| Package | Imported in | Listed in package.json? | How it resolves |
|---------|-------------|------------------------|-----------------|
| `zod` | `src/mcp/server.ts` | ❌ **No** | Hoisted from `@modelcontextprotocol/sdk`'s dependencies |

`zod` is imported directly in `src/mcp/server.ts` (`import { z } from "zod"`) but is not declared in TracePulse's `package.json`. It works today because npm hoists `zod@4.3.6` from `@modelcontextprotocol/sdk`'s dependency tree to the root `node_modules/`. However:

- **pnpm** and **yarn PnP** would fail immediately (strict dependency resolution)
- A future MCP SDK version could drop zod, change its version, or stop hoisting it
- `npm ci` with `--install-strategy=nested` would also fail

### Supply Chain Surface

The main supply chain risk is the **91 transitive production packages** from `@modelcontextprotocol/sdk`. Notable high-value targets in the chain:

- `express@5.2.1` (massive download count, high-value target)
- `cross-spawn@7.0.6` (executes system commands)

These are all well-maintained, widely-used packages. The risk is proportional to any project using the MCP SDK.

## Findings Summary

### F-01: `@eslint/js@10.x` / `eslint@9.x` peer dependency conflict — HIGH

**Package:** `@eslint/js@10.0.1` + `eslint@9.39.4`
**Risk:** `npm ci` fails in CI/CD. `@eslint/js@10.x` requires `eslint@^10.0.0` as a peer dependency. The project pins `eslint@^9.26.0`.
**Remediation:** Either:
- Downgrade `@eslint/js` to `^9.x` to match `eslint@9.x`, OR
- Upgrade `eslint` to `^10.0.0` and update `@eslint/js` together (check typescript-eslint compatibility first)

### F-02: Phantom dependency on `zod` — HIGH

**Package:** `zod@4.3.6` (imported but not declared)
**Risk:** Build works today via npm hoisting, but will break with pnpm, yarn PnP, or if MCP SDK changes its zod dependency. Fragile and non-portable.
**Remediation:** Add `zod` as a direct production dependency:
```bash
npm install zod@^4.3.6
```

### F-03: Wide caret range on MCP SDK — MEDIUM

**Package:** `@modelcontextprotocol/sdk@^1.12.1` (installed: 1.29.0)
**Risk:** Fresh installs can jump 17 minor versions. While semver-compatible, the MCP SDK is pre-1.0-mature and evolving rapidly. A breaking change in a minor release could affect TracePulse.
**Remediation:** Tighten to `^1.29.0` to limit drift. Re-evaluate before TracePulse 1.0.

### F-04: Large transitive production tree (91 packages) — MEDIUM

**Package:** `@modelcontextprotocol/sdk` transitive tree
**Risk:** Increased supply chain attack surface. Express 5, Hono, jose, and other packages are pulled in for HTTP/OAuth features TracePulse doesn't use in stdio mode.
**Remediation:** No immediate action — this is inherent to the MCP SDK's architecture. Monitor for a future SDK option to install a lighter "stdio-only" package. Consider filing an issue upstream.

### F-05: Unused dev dependency `vite-tsconfig-paths` — LOW

**Package:** `vite-tsconfig-paths@^6.1.1`
**Risk:** Unnecessary dependency in the tree. No functional impact.
**Remediation:** Remove it:
```bash
npm uninstall vite-tsconfig-paths
```

### F-06: Dev dependencies behind major versions — LOW

**Packages:** `vitest` (3.x → 4.x available), `typescript` (5.x → 6.x available), `eslint` (9.x → 10.x available)
**Risk:** Missing new features and potential security fixes. No known CVEs currently.
**Remediation:** Plan upgrades as a chore task. Upgrade eslint to 10.x together with F-01 fix. Evaluate vitest 4.x and TypeScript 6.x for breaking changes before upgrading.

### F-07: Source maps in published package — LOW

**Package:** N/A (build output)
**Risk:** Source maps (1.3 MB) account for 65% of unpacked package size. Not a security risk but increases download time for `npx` users.
**Remediation:** Consider adding `*.map` to the `files` exclusion or generating source maps only for development builds. Alternatively, accept the tradeoff for better error diagnostics.

### F-08: MCP SDK bundles two HTTP frameworks — MEDIUM

**Package:** `@modelcontextprotocol/sdk` → `express@5.2.1` + `hono@4.12.15`
**Risk:** Two full HTTP frameworks in the dependency tree for a tool that primarily uses stdio transport. Increases install time and attack surface.
**Remediation:** No action possible from TracePulse side — this is an upstream SDK design decision. Worth monitoring for SDK refactoring that separates transport backends.
