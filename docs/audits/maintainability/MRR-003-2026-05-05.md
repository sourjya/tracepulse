# MRR-003: Maintainability Review - 2026-05-05

| Field | Value |
|-------|-------|
| **Scope** | Full codebase (v0.9.16) |
| **Files reviewed** | 117 source files, 998 tests |

## Findings

### HIGH Severity

#### MRR-003-H1: server.ts is 856 lines (god file)

**File:** `src/mcp/server.ts`
**Issue:** Single file registers all 40 tools with inline handler wiring. Hard to navigate, hard to test individual registrations.
**Impact:** Any change to tool registration requires reading 856 lines of context.
**Recommendation:** Extract tool registrations into per-phase files:
- `src/mcp/register-core-tools.ts` (Phase 1: get_errors, get_server_logs, etc.)
- `src/mcp/register-watch-tools.ts` (Phase 2: verify_fix, watch_for_errors, etc.)
- `src/mcp/register-infra-tools.ts` (infra, probes, health)
- `src/mcp/register-session-tools.ts` (session, patterns, audit)
**Effort:** 2-3 hours. Zero behavior change.
**Status:** Deferred (F-10 in tech debt log)

#### MRR-003-H2: cli.ts is 769 lines (god file)

**File:** `src/cli.ts`
**Issue:** Argument parsing, collector creation, MCP server wiring, HTTP transport, shutdown handling, and the analyze/doctor commands all in one file.
**Impact:** Hard to test individual concerns. Changes to one area risk breaking another.
**Recommendation:** Extract:
- `src/cli/parse-args.ts` (already exported, just move)
- `src/cli/create-collector.ts` (collector factory)
- `src/cli/shutdown.ts` (graceful shutdown handler)
**Effort:** 3-4 hours. Zero behavior change.
**Status:** NEW

#### MRR-003-H3: 103 unchecked type assertions

**File:** Multiple tool handlers
**Issue:** `args.command as string`, `args.limit as number` etc. without null checks.
**Impact:** If Zod validation ever changes or a tool is called without the SDK's validation layer, handlers crash with unhelpful errors.
**Recommendation:** Add defensive null checks on critical params: `const command = args.command as string | undefined; if (!command) return errorResult(...)`. Already done in some handlers but not all.
**Effort:** 1-2 hours.
**Status:** NEW - fix now

### MEDIUM Severity

#### MRR-003-M1: Duplicate `processLine` function

**File:** `src/cli.ts:558`, `src/tools/run-and-watch.ts:163`
**Issue:** Both files have a `processLine` function that strips ANSI, redacts, parses, normalizes, and pushes to a buffer. Nearly identical logic.
**Recommendation:** Extract to `src/pipeline/process-line.ts` shared helper.
**Effort:** 1 hour.

#### MRR-003-M2: DEFAULT_ALLOWED_PREFIXES still exists alongside buildAllowlist

**File:** `src/tools/run-and-watch.ts:66`
**Issue:** The old hardcoded allowlist still exists as a fallback. `buildAllowlist` from `run-and-watch-allowlist.ts` is the new system. Two sources of truth.
**Recommendation:** Remove `DEFAULT_ALLOWED_PREFIXES` from run-and-watch.ts. The `allowedPrefixes` parameter is always provided by server.ts.
**Effort:** 15 minutes.
**Status:** NEW - fix now

#### MRR-003-M3: Inconsistent error response patterns

**File:** Multiple tool handlers
**Issue:** Some handlers return `errorResult("message")`, others return `{ content: [{ type: "text", text: "message" }], isError: true }`. Same intent, different code.
**Recommendation:** All handlers should use `errorResult()` from response-helpers.ts.
**Effort:** 30 minutes.

#### MRR-003-M4: AI-generation artifacts in comments

**File:** Multiple
**Issue:** Some JSDoc comments are overly verbose, restating what the code does. Example: `/** Create a server manager for tracking process state. @returns ServerManager instance. */` on a function called `createServerManager`.
**Impact:** Low - comments are correct, just verbose.
**Recommendation:** No action. Verbose comments are better than no comments for a public project.

### LOW Severity

#### MRR-003-L1: 344 exported symbols

**Issue:** High export count suggests some exports are unused.
**Recommendation:** Run `ts-prune` to find unused exports. Low priority.

#### MRR-003-L2: Test helper duplication

**File:** `tests/helpers/make-event.ts` exists but 24 test files have local `makeEvent` helpers.
**Recommendation:** Migrate to shared helper. Low priority - tests work fine.

## Verdict

**3 HIGH findings** - H1/H2 are deferred (large refactors, no behavior change). H3 should be fixed now.
**4 MEDIUM findings** - M2 should be fixed now (15 min). M1/M3 are cleanup tasks.
