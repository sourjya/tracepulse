## 1. DRR-001 F-02 Resolution: Zod Added as Explicit Dependency ✅

The v0.9.3 release (commit `8d10aab`) added `zod` as a direct production dependency:

```diff
  "dependencies": {
-   "@modelcontextprotocol/sdk": "^1.12.1"
+   "@modelcontextprotocol/sdk": "^1.12.1",
+   "zod": "^4.4.1"
  }
```

**Verification:**

| Check | Result |
|-------|--------|
| Listed in `dependencies` | ✅ `"zod": "^4.4.1"` |
| Installed version | 4.4.1 |
| Recorded in package-lock.json | ✅ With resolved URL and integrity hash |
| Deduplicated with SDK's zod | ✅ Single copy at `node_modules/zod` (4.4.1) |
| Bundle handling | Externalized — `dist/cli.js` imports `from "zod"` at runtime |

**Assessment:** Properly resolved. The phantom dependency risk is eliminated. The declared range `^4.4.1` is appropriate — it allows patch/minor updates within zod 4.x. The SDK's transitive zod dependency is satisfied by the same installed copy (npm deduplication working correctly).

## 2. DRR-001 F-01 Status: ESLint Peer Conflict — Still OPEN ⚠️

**No change since DRR-001.** The conflict persists:

```
@eslint/js@10.0.1 requires peerDependencies: { eslint: "^10.0.0" }
Installed: eslint@9.39.4
```

**Impact confirmed:**
- `npm ci` fails with `ERESOLVE` error
- `npm ls` reports `invalid: eslint@9.39.4`
- `npm install` works (uses legacy peer dep resolution)

**Recommended fix (unchanged from DRR-001):** Downgrade `@eslint/js` to `^9.x` to match `eslint@^9.26.0`. The `@eslint/js@9.39.4` version is already installed as a transitive dep of `eslint@9.39.4` itself, so the explicit `@eslint/js@10.x` declaration is redundant and conflicting.

## 6. Bundle Size Impact

### Current (v0.9.3)

| Artifact | Size |
|----------|------|
| `dist/cli.js` | 182 kB |
| `dist/cli.js.map` | 468 kB |
| `dist/index.js` | 124 B |
| Published tarball (gzipped) | 177.6 kB |
| Unpacked size | 740.4 kB |
| Total files | 23 |

### Comparison with DRR-001 (v0.9.2)

| Metric | v0.9.2 (DRR-001) | v0.9.3 (DRR-002) | Delta |
|--------|-------------------|-------------------|-------|
| `dist/cli.js` | 675 kB | 182 kB | **-493 kB (-73%)** |
| `dist/cli.js.map` | 1.3 MB | 468 kB | **-832 kB (-64%)** |
| Published tarball | 360.9 kB | 177.6 kB | **-183.3 kB (-51%)** |
| Unpacked size | 2.1 MB | 740.4 kB | **-1.36 MB (-65%)** |

**Analysis:** The dramatic size reduction is because zod is now **externalized** rather than bundled. In v0.9.2, tsup inlined zod into `dist/cli.js` (since it wasn't in `dependencies`, tsup treated it as application code). Now that zod is a declared dependency, tsup correctly externalizes it — the bundle just contains `import ... from "zod"` and the actual zod code is loaded from `node_modules/` at runtime.

This is the correct behavior for an npm package: declared dependencies are resolved at install time, not bundled. The 73% reduction in CLI bundle size is a direct positive consequence of fixing F-02.
